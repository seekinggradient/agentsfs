# Documentation audit — 2026-07-28

> **Archived audit.** This is the audit that produced the current three-tier docs layout;
> the problems it catalogues have been fixed, so its file inventory and line citations
> describe the tree as it was, not as it is. Start at [../README.md](../README.md).

Scope: `README.md`, all 21 files in `docs/`, the five topics reachable through `afs docs`, the Hub's in-product copy (`internal/hub/assets/`), the public site at `agentsfs.ai` (`agentsfs-landing`), and the stale `hosted-hub` worktree at `~/Development/agentsfs-hub`. Every claim below is anchored to a file:line or a live check.

## Verdict

The documentation is accurate about the things that were built first and wrong about the things built most recently. Files describing the CLI, the contract, and the on-disk layout hold up under line-by-line verification. Files describing the Hub and the hosted agent describe a topology that was switched off weeks ago. Nine of the 21 files in `docs/` are historical plans and build logs sitting on the same shelf as live reference, with no banner or index telling a reader which is which — `docs/agentsfs-source-of-truth.md:3` still opens with "Ideation is complete; the next phase is execution planning" while the CLI is at v0.10.0 and the Hub serves production traffic.

The single biggest problem is that `docs/hub.md` is both the binary's only description of the hosted agent and materially false. It ships inside every `afs` release (`embed.go:17`), it is the `afs docs hub` topic (`internal/docs/docs.go:35-38`), and at line 62 it tells the reader the Hub "spins up your own private agent — a hardware-isolated sandbox that clones all of your Hub repos." Production sets `HUB_EVE_AGENT_URL`, which short-circuits the entire sprite path at `internal/hub/web.go:1342-1344` before any provisioning runs. Nothing is spun up per user, nothing is hardware-isolated, and nothing is cloned. The same paragraph's "no LLM keys ever live on the agent" is false in the same mode. An agent that reads the bundled docs to learn what the Hub does learns a retired architecture.

The highest-leverage fix is not a rewrite of that file — it is creating the two documents that do not exist. There is no capability catalog and no glossary. Every recurring error in this audit traces back to one of those absences: the parity claim ("CLI + MCP, same capabilities on both surfaces," `agentsfs-source-of-truth.md:86`) exists because no document ever laid the four surfaces side by side, and the instance/knowledge-base/repo/memory drift exists because no document ever defined them. Write `docs/capabilities.md` and `docs/concepts.md`, register them as `afs docs` topics, and roughly half the accuracy findings below become impossible to reintroduce.

Two structural facts about `afs docs` matter for everything downstream. The embed glob is `docs/*.md` (`embed.go:17`), and Go's `path.Match` does not cross `/` — verified empirically — so a file moved into `docs/archive/` silently leaves the binary with no build error. And the topic list is a hardcoded five-entry slice, not derived from the embed FS the way `afs skills` derives its list from `SkillsFS`, which is why `docs/archive/hub-mcp.md` and `docs/internals/releasing.md` are shipped-but-unreachable.

The `hosted-hub` worktree can be deleted outright. `git diff --name-status main hosted-hub` yields 139 deletions, 80 modifications, and zero additions; its only unique commit (`75ca883`, contract 0.6.0) is preserved byte-identically on main at `internal/core/contracts/AGENTS-0.6.0.md`. The one item worth extracting before deletion is a security note in its `docs/how-the-hub-works.md` §8 asking that Cloudflare and Fly tokens be rotated because they passed through a chat log. Whether that was ever done is unconfirmed.

## Writing quality

Five patterns recur across the corpus. Each is illustrated once.

**Register whiplash inside a single file.** Marketing copy and shell scripts share a page with no seam. `README.md:23` closes the philosophy section with "That is the whole primitive: slightly opinionated where the opinions matter, portable across operating systems and agent harnesses, and intentionally cut down to the smallest useful shape" — forty lines above a bash conditional testing `afs help | grep -q "afs status"`. `docs/how-the-hub-works.md` pivots from "A private GitHub, but for your agents' knowledge instead of code" to compare-and-swap conflict semantics within one screen. The reader cannot calibrate how literally to take any given sentence.

**Lists unrolled into prose.** The corpus consistently packs enumerable content into single sentences. `docs/agent-start.md:13` chains eight independent contract rules through commas: "read before acting, write dense Markdown notes with `description:` frontmatter, use `[[wikilinks]]`, cite sources, improve existing notes instead of appending noise, reorganize the knowledge base as it grows, finish each unit of work with a short session note…" — the underlying `template/AGENTS.md` presents the same material as twelve numbered rules. `docs/archive/hub-mcp.md:40` chains six distinct OAuth facts across ~90 words with PKCE, DCR, CIMD, and SSRF all unexpanded. `docs/internals/how-deployment-works.md` lists nine redeploy triggers in one comma sequence.

**Undefined load-bearing jargon.** Terms are used before, or entirely without, definition. "Gardener" is used at `README.md:243` ("the gardener's worklist") and defined nowhere in that file. "Harness" appears at `docs/setup.md:45` and lands cold on human readers at :293. "The contract" is load-bearing throughout `README.md` and never equated to `template/AGENTS.md`. `docs/internals/agent-review-mode.md:61` uses "CAS" five lines before spelling it out; `docs/internals/kb-access-and-isolation.md` never spells it out in body prose at all.

**Stale framing outliving accurate bodies.** Several documents are correct in substance and wrong in their opening and closing sentences — the parts a skimmer reads. `docs/agentsfs-source-of-truth.md` carries inline 2026-07-04 revisions in its body while its header and Status section still say ideation is complete and an execution plan is pending. `docs/archive/build-report-layers-2-4.md` was edited on 2026-07-11 to update one Layer 4 bullet while its "Open items carried forward" list — already falsified a month earlier — was left untouched. A partial touch-up is worse than none: it signals review and implicitly endorses the stale parts.

**The same fact written twice, differently.** `afs status`'s flags are explained in prose at `README.md:39-41` and again as a table cell at `README.md:237`. `docs/setup.md` explains `--json`/`--doctor`/`--fetch` once per audience track, ~85 words apart. The Eve request path is described in near-identical but non-identical wording in `docs/internals/hosted-agent.md:13-25`, `docs/internals/eve-hosting.md:32-46`, and `docs/how-the-hub-works.md` §7. These will diverge on the next edit to any one of them; the wikilink finding above is what that looks like after it has already happened in code.

Two things are worth preserving deliberately. `docs/internals/eve-hub-integration.md` and `docs/internals/agent-review-mode.md` are dense, precise, code-verified, and honest about what is historical — they are the standard the rest should meet. And the landing site's hygiene checker (`scripts/check-hygiene.mjs:32`) bans "amnesiac," "revolutionize," "unleash," "supercharge"; a grep for the full AI-marketing buzzword set across every copy file in that repo returns zero hits. That discipline is unusual and should not be lost in any rewrite.

## Coverage gaps

Ranked by who they block.

**Blocks agents (the primary consumer).**

1. **`afs search --context[=N]` — zero documentation anywhere.** The flagship agent-facing retrieval feature. `afs help` calls it search's headline (`internal/docs/docs.go:64`), and a grep for `--context` across `README.md`, `docs/`, `template/`, `prompts/`, `skills/`, `deploy/`, and the landing site hits only this audit's own artifacts. Undocumented: the 4000-token default, the `ContextPack` JSON shape, that oversized docs contribute only their matched section, that `--semantic` is silently ignored, and that the space form `--context 200` silently ignores the budget and is consumed as the `[path]` argument. The entire multi-signal ranking pipeline (body FTS + description + 1-hop wikilinks + structural priors + the 0.35 contract demotion) is likewise undocumented.
2. **The local `afs mcp` server.** Twelve tools ship; five are documented, in `docs/hub.md`. And nothing in the repo writes an `mcpServers` block — a repo-wide grep returns nothing — so there are no wiring instructions at all for the feature `README.md:248` advertises as "for harnesses that can't shell out."
3. **`afs contract status`/`diff` and the `--yes`/`--force` flags.** Absent from `afs help` (`internal/docs/docs.go:72`) and from every doc except `prompts/gardening.md`. A non-interactive agent cannot discover how to run a contract upgrade unattended.
4. **`afs roles` is missing from README's toolkit table.** The one command the contract explicitly tells tool authors to call instead of hardcoding `agent-journal/` is absent from the integrator-facing table.

**Blocks end users.**

5. **`docs/archive/hub-mcp.md` is an orphan.** Accurate content, zero inbound links — not in README's docs index, not an `afs docs` topic, referenced by nothing. Connecting claude.ai or ChatGPT is the lowest-friction on-ramp to the whole product and is invisible from every entry point a user reads. The endpoint is live (verified: `/.well-known/oauth-protected-resource/mcp` returns correct metadata).
6. **Collaborator sharing, owner side.** `docs/hub.md` mentions collaborators four times, all from the recipient's perspective. Settings → add by email, read/write roles, the `/invite/<token>` link, and the generated agent handoff prompt appear nowhere. `docs/how-the-hub-works.md:217` files collaborators under "not done yet."
7. **Hub web features with no description anywhere:** the interactive wikilink graph and sortable table views (`repo.html:17-18`), per-file export to markdown/PDF/DOCX (`export.go:49-68`), the LFS-resolving repo ZIP, repo slug rename with 301 redirects for git and LFS but *not* for browser bookmarks, and soft delete to `.trash/`. Grep for `graph`, `docx`, `ZIP`, `rename redirect` across reader-facing docs returns nothing.
8. **Review mode's trigger.** The mechanism is explained in three sentences in `how-the-hub-works.md`; nothing tells a user the "Comment for agent" button exists, where, or who sees it.

**Blocks operators.**

9. **`deploy/self-host.md` documents only the retired agent backend.** Zero occurrences of Eve. It states the agent feature "reports as enabled only when `SPRITES_TOKEN` + `OPENAI_API_KEY` are" set. Following the only self-hosting doc gets the fallback topology or nothing.
10. **Signup gating.** `AFS_HUB_ALLOWLIST`, `AFS_HUB_OPEN_SIGNUP`, the waitlist, and invite redemption have zero coverage in any reader-facing doc, while `docs/hub.md:58` promises self-serve signup.
11. **`/admin` console.** `/admin/metrics` (per-user LLM cost telemetry) and `/admin/access` (allowlist/waitlist management) plus `HUB_ADMIN_USER` have zero coverage. The only `admin` string in `how-the-hub-works.md` is under "deliberately not done yet."

**Blocks new developers.**

12. **`afs doctor`'s output contract** — the finding codes, the severity model, and the load-bearing rule that doctor exits non-zero for exactly one code (`duplicate-role`) — exists only in `prompts/gardening.md`. Adequate for a gardener agent, invisible to anyone reading `docs/`.
13. **Assorted CLI surface:** `AFS_NO_UPDATE_CHECK` (the only way to silence the nudge in CI), the `AFS_EMBED_*` overrides and `embeddings.env` path, that Voyage silently wins when both keys are set, exit-code semantics, `afs hub logout` (documented only inside `afs hub help`, and it does not remove the global git credential helper it installed), and the dashboard's `?format=json` machine surface.
14. **No LICENSE file exists in the repo root**, and README has no License or Contributing section. A reader cannot tell whether they may use or fork the project.

## Terminology

The proposed canonical glossary. Each term is defined once in `docs/concepts.md` and used consistently everywhere else.

| Concept | Canonical term | Rule |
|---|---|---|
| The product | **AgentsFS** | Title Case in prose, including sentence starts. Lowercase `agentsfs` only for the repo-name convention (`~/agentsfs`, `.agentsfs/`) and the established "an agentsfs" common-noun idiom — which should be written down as a rule, not inferred |
| The CLI | **`afs`** | Always lowercase, always code font. Not a brand abbreviation |
| The core object | **knowledge base** (two words) | For end users, README, landing site, Hub UI copy |
| — same object, technical prose | **instance** | For CLI/contract docs where scoping reads better ("every instance beneath this directory") |
| — same object, git context | **repo** | Only when the subject is genuinely git hosting: push, pull, clone, remotes |
| Hosted service | **Hub** | Capitalized as a product name; lowercase inside commands (`afs hub push`, the `hub` remote) |
| Versioned ruleset | **contract** | The rules in `template/AGENTS.md`, versioned independently of the CLI |
| Starter file set | **template** | What `afs init` writes to disk; the carrier of the contract |
| Markdown knowledge unit | **note** | Already encoded in code: `file.html:54` renders "Markdown note" vs "Text file" vs "File" |
| Any file | **file** | The superset |
| External source material | **document** | Never AgentsFS's own stored content |
| Pre-existing Obsidian folder | **vault** | Always someone else's folder being adopted — never AgentsFS's own object |
| The user's coding AI | **agent** | Claude Code, Codex, etc. This is how `template/AGENTS.md` already uses it throughout |
| The hosted chat product | **Eve** (or "the Hub agent") | Needs a name in the UI, not just in prose |
| Agent runtime | **harness** | Define on first use; currently undefined for human readers |

Terms currently ambiguous, in order of damage:

**"agent" means two unrelated things.** Sense A is the user's own coding AI — the entire premise of the product. Sense B is the hosted Vercel app, code-named Eve in prose (`README.md:191`, `docs/internals/hosted-agent.md`) but never called Eve in the product: `base.html:42` renders a bare `Agent` button, `base.html:48-53` a bare `Agent` dock, and grep finds zero occurrences of "Eve" anywhere in `internal/hub/assets/` or in the landing site. Brand name in the docs, overloaded generic noun in the product, is the worst of both.

**"instance" vs "knowledge base" collide inside the files that ship into every new repo.** `template/INDEX.md:7` uses both, twenty words apart: "a one-line summary of what this **instance** is about… it is what `afs tree`, `afs status`, and the Hub show as this **knowledge base's** label." `template/AGENTS.md:14-36` alternates across a single paragraph. Rough corpus counts: repo/repository ~335, instance ~154, knowledge base ~83. The Hub UI uses "repository" for chrome and "knowledge base" for anything agent- or OAuth-adjacent (`consent.html:14`, `repo.html:9`) — and mixes both in one sentence at `dashboard.html:116`: "No repositories yet. The first push creates a private knowledge base." The CLI's own word, "instance," appears zero times in the Hub UI.

**"KB" means both knowledge base and kilobytes**, in the same file. `docs/internals/hub-repoview-performance.md:64` says "400 KB response"; :79 says "Large KBs still felt like they froze the site." Ban the abbreviation.

**Tool names disagree across agent surfaces.** `docs/internals/hosted-agent.md:51` names `list_repos`, `focus_repo`, and `create_kb`; `internal/hub/mcpapi.go:368` exposes `list_kbs`. Three names for one object across two tool sets.

Smaller: "knowledgebase" as one word appears at `internal/docs/docs.go:59`, `README.md:183`, and `docs/internals/eve-hub-integration.md:197`, one line from "knowledge bases" in the first case. Lowercase `agentsfs` starts sentences at `agentsfs-source-of-truth.md:46,68` and `setup.md:330`. `docs/archive/hub-ui-audit-2026-07-27.md:1` is titled "agentsFS." "Workspace" is used correctly and consistently for the project directory an agent works in — a real fourth concept that should *not* be folded into the pile.

### Code changes

**`embed.go` — no edit required, and that is the point.** The glob is `docs/*.md`, and Go's `path.Match` does not cross `/` (verified empirically: `docs/*.md` matches `docs/top.md`, not `docs/archive/old.md`). Files moved into `docs/internals/` and `docs/archive/` drop out of the binary automatically; new files added at `docs/` root are picked up automatically. Do **not** "fix" this to `all:docs` — the glob is what makes the tier boundary self-enforcing. A build error only occurs if a pattern matches zero files, so nothing here can break silently in the other direction.

### Briefs for new files

**`docs/capabilities.md`** — the centerpiece, and the document whose absence causes the most errors. A matrix organized by *task*, with one column per surface: `afs` CLI, local `afs mcp`, Hub web + git, Hub `/mcp` + `/api/agent/v1`. Rows are intents, not commands: orient / search / retrieve a context pack / read a file / write or commit / check health / find backlinks / rename with link rewrite / resolve roles / sync to a remote / share with a person / browse / talk to an agent / connect ChatGPT or Claude. Every cell is a tool name or an explicit "—". Its single most important job is to kill the parity assumption: state outright that the CLI has ~20 commands, local MCP has 12 tools, Hub MCP has 5-6 (write only with `afs:write`), that the two MCP servers share only `docs` and `tree` with *different schemas*, that local MCP has no write-to-KB tool, and that the Hub has no `doctor`/`roles`/`backlinks`/`rename`/`status`. Name what exists in exactly one place: `--context` packs (CLI and agent API, not MCP), semantic search (CLI only), CAS commits (Hub only), collaborators (Hub only). Close with a short "deliberately not here" list: the walker ignores `.gitignore`, there is no incremental indexing, and only `*.md` is indexed — PDFs and images are invisible to search.

**`docs/concepts.md`** — the prerequisite read every other doc assumes and none provides. Twelve terms, 2-4 sentences each, per the glossary above. Must include the four hard rules that are currently tribal knowledge: roles are found by marker not name (call `afs roles --json`, never hardcode `agent-journal/`); the contract version and the CLI version are different numbers that drift apart (today 0.9.0 and 0.10.0); `afs doctor` exits non-zero for exactly one finding code, so a zero exit is not a pass; and a bare `AGENTS.md` does not make a directory an instance — `.agentsfs/` does. End with a "what AgentsFS is not" list: not a database, not a vector store, not hosted-only, no intelligence inside the filesystem.

**`docs/cli.md`** — every command in the `Commands()` slice, in the same group order, with the full flag list *including the flags missing from help today* (`afs contract upgrade --yes/--force`, `--version`/`-v`/`--help`/`-h`, `tree -d`, `search --limit`, `hub link`/`clone`/`get`/`repos`/`ls`, `hub pull --vendor`), exit-code semantics, and a "surprises" line wherever one exists: `afs search` writes `.agentsfs/index.db`; `afs skills list` materializes to disk despite the name; `afs hub login` mutates global git config and `afs hub logout` does not undo it; `afs status --fetch` is the only network path; `afs search <q> --context N` silently ignores the budget.
