## Learned / decided
- Phase 1 Hub side of the Markdown To integration is code-complete (commit f539f76), built as a fourth thin transport over `internal/hub/repoaccess.go` — the capability layer absorbed a browser-editor surface without change, which is the architecture paying off.
- Decisions taken where the contract was open (full detail in docs/internals/save-api.md):
  - **SPA token custody**: standard PKCE — 2h access + 30d rotating refresh with family reuse-revocation (the AS-wide values; no per-client TTL column). `Access-Control-Allow-Credentials` is never sent, so cookies can't be substituted. Playground guidance: access token in memory, refresh in sessionStorage.
  - **If-Match**: create-without-If-Match allowed (201); overwrite without it is **428 Precondition Required** carrying the current hash+rev so the correct retry is one step; mismatch is 412 with the same body. Hash is `sha256hex(bytes)` — byte-identical to the patch engine's `sourceHash`, pinned by a known-answer test. `ETag` quoted + `X-Afs-Source-Hash` bare, both CORS-exposed.
  - **Scopes**: `instances:*`/`sharelinks:create`/`profile` are new values, deliberately disjoint from `afs:*` — a browser-editor token can't drive MCP tools. PATs get the save scopes but never `sharelinks:create`: publishing stays a human-at-a-browser act.
  - **Defaults**: instance `apps`, saves dir `apps/` (both single constants; flagged to the owner that the default path reads `apps/apps/x.md`). Bootstrap is idempotent, seeds the real contract template, and the created instance passes real `core.Doctor` (mutation-tested).
- Enabling hooks for phase 2 rendering: `readFileMeta`/`envelopeKey` make the `markdownto:` envelope a first-class thing the Hub reads (core frontmatter parser, no new parsing); PUT responses report `"collection"` so a save outside a collection dir is visible to the client.
- **Not deployed.** `fly deploy --app agentsfs-hub --remote-only` per fly.toml is the documented path; changes are additive (legacy `allow_write` consent alias kept, /mcp PRM not widened). Deploy + live verification is the next step; the orchestrating session handles it.
