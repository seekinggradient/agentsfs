## Intent

Make a `guided-narration@0.1` manuscript usable as a guided reader on a Hub page.
Re-vendoring the September 20 bundle (three commits already on main) made the
Hub *render* the reader; it did not make it work. Two things were missing and
neither was a rendering change: the reader's script could not run under the
read-only sandbox, and the source article it is forbidden to fetch was not on
the page.

## Progress

**A. Go supplies the source article** (`internal/hub/mdtoview.go`).
`handleMdtoView` resolves the manuscript's `source:` frontmatter against its own
directory and puts the article on `#mdto-source` as `data-guided-source-b64`,
beside `data-guided-source-ref` carrying the exact string it resolved from.
Read through `core.FrontmatterValueFromReader` — a real YAML parser — so a
quoted scalar resolves and echoes identically to a bare one; a line scanner
would have handed the reader a ref with quotes on it and left it waiting
forever. Refused before `path.Join` can normalise anything away: `..`, absolute,
scheme, query, fragment, backslash, control character, non-`.md`, over
`maxMdtoBytes`, invalid UTF-8. An `https://` source is valid per the spec and
names nothing here, so it is treated as absent.

**B. view.js answers the handshake.** The reader posts `guided-ready` as it
loads and then waits, so the listener is installed *before* the frame is
mounted. Two guards: window identity (the frame is opaque-origin, so
`event.origin` is the string "null" and worth nothing) and the source string.
`guidedSourceBridge` is asked for **only** when there is an article, so every
refusal above lands on the reader's own intake form rather than a permanent
wait — the failure mode that arrangement exists to make unreachable.
`guided-source`/`guided-auth`/`guided-audio` reach no listener, the same
deliberate silence `mdto:'key'` gets.

**C. The third variant.** `#mdto-guided` carries
`sandbox="allow-scripts allow-downloads"` and `data-allow="autoplay"`, authored
in markup like the other two, for every viewer of a guided manuscript.
`mdtoGuidedCSP` is `mdtoCSP` with exactly three substitutions —
`script-src 'self' 'unsafe-inline'`, `img-src` + `blob:`, `media-src` +
`blob: data:` — and `connect-src 'none'` **does not move**: a guided page has
nothing to save, so it has no reason to loosen the one directive that would let
its frame speak to this Hub. A writer keeps the live variant. `isLive` now says
out loud that a `result.guidedNarration` is never live.

**D. Tests.** Source byte-fidelity and ref equality; a quoted `source:`; nine
refusal cases; a per-viewer variant test (read collaborator, anonymous on a
public instance, owner, write collaborator, and a kanban board for the same
reader, unchanged); the CSP delta asserted as a whole, not only directive by
directive; `guidedRelativeSource` unit cases; loader-bytes needles.
Five removals verified red: the resolver, the guided CSP, the `#mdto-guided`
element, the `guided-restore` reply, and the `isLive` guard.

**E. Browser proof** — local `afs-hub`, real git push, `afs-hub.visibility
public`, headless Chromium via the CloudWindow checkout's Playwright,
**anonymous**. Frame sandbox `allow-scripts allow-downloads`, `allow="autoplay"`,
no `#mdto-live`. Inside the reader: `location.origin === "null"`,
`parent.document` and `document.cookie` each throw `SecurityError`. Zero CSP
violations on all four pages tested. The article mounted: 98 blocks, 33,791
characters, 3 chapters, 6 passages. The Next control advanced beat 0 -> 1 and
highlighted the target block. Play spoke all six beats in authored order. The
audio strip and the reader coexist on the same page. A manuscript whose
`source:` names nothing drew the intake form immediately — no hang.

## Discoveries

**markdownto's markdown importer drops soft-break whitespace.** A hard-wrapped
article comes back with its wrapped words joined ("at the\nmoment" ->
"at themoment"), so any `[target-quote::]` spanning a wrap matches nothing, and
the reader's source load is all-or-nothing. **19 of 54** beats of
`cloudwindow-architecture.guided-narration.md` fail this way; **all 54** resolve
when the identical manuscript in the identical reader is handed that article's
committed capture JSON instead. That isolates it to the importer: the bytes the
Hub delivers are byte-identical either way. Recorded as
`[[backlog/INDEX#^guided-markdown-softbreak]]`.

**The Hub must not work around it.** Unwrapping would alter the file on the way
to the parser, which is the one thing the whole page refuses to do; deriving
blocks in Go would mean owning a renderer. A capture beside the article would
fix it but there is no convention for where such a file lives, and a
Hub-invented one is the mistake `narrate-artifacts@0.1` already learned once.

The reader also logs a permissions-policy message for `screen-wake-lock`, which
is deliberately not delegated. Headless Chromium has no TTS engine
(`getVoices()` is 0, a real utterance returns `synthesis-failed`), so beat
advancement under Play was observed with a stand-in voice; advancement through
the player's own Next control was observed with no substitute of any kind.

## Decisions

- Share links left alone. Serving a sibling through a token means deciding
  whether that token's scope covers it — a real authorization question, not the
  same code — and a share link has never been given a frame that runs script.
- `isGuidedNarration` lives in `narrate_artifacts.go` beside the artifact roots,
  so every spec name the Hub knows has one home. Naming one spec was the
  smallest of three bad options; the other two were widening the sandbox for
  every read-only document, or letting `view.js` compose a literal.
- Per-beat audio inside the reader left unbuilt, as scoped. The handshake reply
  is built from one object so that phase adds a field in one place.

## Open
